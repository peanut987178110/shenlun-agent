# 1. 产品概述

## 1.1 产品名称

暂定名称：浙考申论智阅

产品定位：

> 面向浙江省公务员考试申论备考用户，提供“拍照上传—智能识别—证据化批改—能力诊断—二次修改—个性化训练”的 AI 智能学习系统。

产品不是单纯的作文批改工具，而是一个结合以下能力的智能体：

- 浙江省考申论题库
- 手写答题识别
- 题型识别
- 评分标准解析
- 得分点证据匹配
- 红线批注
- 评分争议复核
- 错误因果诊断
- 修改增分预测
- 个性化训练
- 长期学习画像

## 1.2 产品愿景

让用户每完成一道申论题，都能明确回答：

1. 我得了多少分？
2. 为什么得这个分？
3. 哪些内容没有得分？
4. 最先改哪里最划算？
5. 下次怎样避免同类问题？
6. 我是否真的具备迁移能力？

## 1.3 核心价值

| 用户痛点 | 产品解决方案 |
|---|---|
| 人工批改贵、等待时间长 | AI 即时批改 |
| 评分结果不透明 | 得分点证据链 |
| 只知道错，不知道为何错 | 错误因果诊断 |
| 看完答案不会迁移 | 二次修改与回归测试 |
| 题目推荐不精准 | 能力处方 |
| 不知道如何提高几分 | 反事实增分建议 |
| 浙江省考标准适配不足 | 地区、年份、类别评分配置 |
| 不信任 AI 分数 | 评分区间、置信度、申诉复核 |

# 2. 市场与竞争分析

## 2.1 市场现状

市场上的申论产品已经普遍具备：

- 真题题库
- 题目解析
- 拍照上传
- OCR 识别
- AI 评分
- 作文点评
- 错题本
- 学习规划
- AI 对话
- 人工批改

因此，“支持拍照上传并自动打分”不具备明显竞争力。

## 2.2 本产品的竞争定位

竞品重点关注：

```text
题库 → 作答 → 批改 → 报告
```

本产品重点关注：

```text
作答 → 评分证据 → 失分机制 → 最小修改 → 增分验证 → 能力迁移
```

## 2.3 核心差异化

### 差异化一：可审计评分

每个得分点都能追溯到：

- 题目要求
- 材料段落
- 用户原文
- 评分规则
- 得分判断

### 差异化二：错误因果诊断

不只标注“对策空泛”，还判断：

- 是没找到问题主体；
- 还是不会将问题转化为措施；
- 还是缺少执行性思维；
- 还是受字数限制导致压缩过度。

### 差异化三：反事实增分

告诉用户：

- 改哪句话；
- 预计增加多少分；
- 需要多少时间；
- 哪种修改性价比最高。

### 差异化四：答案版本管理

比较：

- 原始答案；
- 用户自改答案；
- AI 指导答案；
- 限时重写答案；
- 隔周迁移答案。

### 差异化五：争议评分复核

允许用户挑战 AI 的判断，并形成：

- AI 初评；
- 用户异议；
- 材料重检；
- 第二模型复核；
- 教师复核；
- 最终评分。

### 差异化六：能力处方

不再简单推荐“再做几道题”，而是生成有目标、有步骤、有通过标准的训练方案。

# 3. 产品目标与非目标

## 3.1 V1 产品目标

第一阶段聚焦浙江省考申论，完成以下闭环：

1. 支持手写答题卡拍照上传。
2. 自动识别题目和答题内容。
3. 支持浙江省考主流申论题型。
4. 根据题型生成不同评分规则。
5. 输出可解释的分项评分。
6. 对答案进行分层红线标注。
7. 展示材料—答案—得分点对应关系。
8. 支持用户二次修改。
9. 生成修改前后对比。
10. 形成个人错误模式库。
11. 推荐下一阶段训练。
12. 对低置信度结果进行人工或高级模型复核。

## 3.2 V1 非目标

以下内容暂不作为第一阶段重点：

- 覆盖全国所有省份；
- 自动替代人工阅卷；
- 精确预测正式考试分数；
- 直接生成整篇答案作为主要学习方式；
- 完成所有公职考试科目；
- 支持复杂线下课堂管理；
- 处理无法确认来源的“内部评分规则”。

## 3.3 产品边界

系统输出应统一使用：

- 预计得分；
- 分数区间；
- 模拟评分；
- 评分置信度；
- 参考性建议。

不得宣称：

- 正式考试真实分数；
- 与官方阅卷完全一致；
- 绝对正确；
- 能保证上岸。

# 4. 用户与使用场景

## 4.1 目标用户

### 用户 A：基础备考者

特征：

- 第一次系统准备申论；
- 不熟悉各题型；
- 不知道什么是得分点；
- 容易依赖参考答案。

核心需求：

- 逐步讲解；
- 术语解释；
- 句子改写；
- 题型训练；
- 及时反馈。

### 用户 B：中等水平考生

特征：

- 已经完成一定数量真题；
- 成绩长期处于中低区间；
- 知道基本方法但无法稳定得分；
- 常犯相同错误。

核心需求：

- 找到反复失分机制；
- 分析分数卡点；
- 高性价比训练；
- 旧题重做；
- 能力迁移验证。

### 用户 C：冲刺考生

特征：

- 距离考试时间短；
- 有明确目标分；
- 关注限时作答和全卷表现；
- 不希望阅读过长报告。

核心需求：

- 快速批改；
- 得分优先级；
- 时间分配分析；
- 考场模拟；
- 重点问题提醒。

### 用户 D：教师或机构

特征：

- 批改量大；
- 需要统一评分；
- 需要掌握学生共性问题；
- 希望减少重复性工作。

核心需求：

- 批量批改；
- 人工复核；
- 自定义评分标准；
- 班级数据；
- 教学报告。

## 4.2 核心用户故事

### 用户故事 1：拍照批改

作为浙江省考考生，我希望将手写答题卡拍照上传，以便不用重新录入答案就能获得批改结果。

### 用户故事 2：理解扣分

作为考生，我希望知道每一处扣分对应哪一条材料和评分规则，以便判断 AI 是否批改合理。

### 用户故事 3：修改答案

作为考生，我希望系统告诉我如何修改原答案，而不是只给一份参考答案。

### 用户故事 4：判断进步

作为考生，我希望知道修改后是否真的提高了能力，而不是只在原题上看起来更好。

### 用户故事 5：教师复核

作为教师，我希望快速查看 AI 的低置信度评分，并修改其中不合理的判断。

# 5. 浙江省考适配策略

## 5.1 适配原则

由于不同年份、类别和地区可能在题型、分值和命题重点上存在变化，系统不能将某一年度规则固定为永久标准。

所有批改都必须基于：

```text
考试类型 + 年份 + 类别 + 题目版本 + 评分规则版本
```

## 5.2 支持的配置维度

- 浙江省考；
- 考试年份；
- 试卷批次；
- 省级机关；
- 市县机关；
- 乡镇机关；
- 综合管理类；
- 行政执法类；
- 其他经确认的类别；
- 用户自定义试题。

最终上线前，应由浙江省考教研人员确认具体题型和评分配置。

## 5.3 题目匹配层级

### 一级：精确匹配

匹配：

- 年份；
- 地区；
- 类别；
- 题号；
- 原题文本；
- 材料文本。

### 二级：文本匹配

通过题干和材料相似度匹配历史题目。

### 三级：题型匹配

无法匹配原题时，仅使用：

- 题型规则；
- 用户提供的题干；
- 通用申论评分标准。

此时必须降低评分置信度。

# 8. 功能需求详细设计

## 8.1 首页

### 页面目标

帮助用户快速开始训练，并了解近期学习状态。

### 页面内容

- 目标考试；
- 目标分数；
- 当前平均分；
- 最近一次成绩；
- 分数趋势；
- 高频错误；
- 待复盘题目；
- 今日训练处方；
- 快速批改入口；
- 全卷模拟入口。

### 核心交互

用户首次进入时，需要设置：

- 考试年份；
- 考试类别；
- 目标地区；
- 目标分数；
- 当前基础；
- 预计考试时间。

### 验收标准

- 用户可在 60 秒内完成目标设置；
- 首页显示至少 3 项个性化信息；
- 点击“开始批改”不超过两步进入上传页面。

---

## 8.2 上传与图像质量检测

### 支持格式

- JPG；
- JPEG；
- PNG；
- PDF；
- 相机连续拍照；
- 多页图片。

### 检测项目

- 清晰度；
- 反光；
- 阴影；
- 倾斜；
- 页码；
- 内容完整性；
- 图片重复；
- 手写区域；
- 字符可识别度；
- 是否存在裁切。

### 图片质量等级

| 等级 | 说明 | 系统行为 |
|---|---|---|
| A | 可稳定识别 | 允许批改 |
| B | 大部分可识别 | 提示风险后允许继续 |
| C | 关键内容可能丢失 | 要求重新拍摄或手动确认 |
| D | 无法识别 | 禁止开始批改 |

### 关键交互

系统不只提示“图片模糊”，而要定位：

> 第 2 页中下部（约 50%—62% 高度）存在反光，可能影响该区域文字识别。

【修订】质量检测发生在 OCR 之前，此时拿不到行号，只能按页面区域定位。OCR 完成后，低置信度内容再精确到行（见 8.3）。

## 8.3 OCR 与识别结果确认

### OCR 输出

- 文字内容；
- 行号；
- 段落；
- 页码；
- 字符置信度；
- 识别异常；
- 原图定位。

### 识别结果展示

左侧显示原图，右侧显示识别文本。

低置信度文字使用黄色下划线标记。

用户可以：

- 点击原图定位；
- 修改文字；
- 合并段落；
- 拆分段落；
- 删除草稿；
- 标记非答案内容；
- 重新识别。

### OCR 失败处理

系统允许：

- 重新拍摄；
- 手动输入；
- 仅对可识别部分批改；
- 提交人工录入；
- 继续但降低置信度。

- 类别；
- 题号；
- 匹配度；
- 题型；

- 已精确匹配；

### 用户确认

用户必须确认：


## 8.5 AI 题型识别

系统输出：

- 题型；
- 识别依据；
- 核心任务；
- 评分重点；
- 字数和格式要求。

示例：

```text
识别题型：提出对策题
题目任务：针对材料反映的问题提出改进措施
重点评分：
1. 问题对应性
2. 对策具体性
3. 执行主体
4. 措施可操作性
5. 材料依据
```

用户可以手动修改题型。

# 9. 分题型批改设计

## 9.1 归纳概括题

### 评分维度

- 要点覆盖；
- 要点准确；
- 概括程度；
- 分类整合；
- 材料边界；
- 语言规范；
- 字数控制。

### 输出内容

- 得分点矩阵；
- 命中、部分命中、未命中；
- 材料定位；
- 多余表达；
- 推荐压缩版本；
- 最小修改方案。

### 特殊识别

系统需要区分：

- 原文摘抄；
- 有效概括；
- 案例复述；
- 主观延伸；
- 空泛总结；
- 要点重复。

---

## 9.2 综合分析题

### 评分维度

- 核心观点理解；
- 概念解释；
- 材料联系；
- 原因分析；
- 影响分析；
- 辩证分析；
- 结论回应；
- 逻辑完整性。

### 常见错误

- 只解释字面意思；
- 只复述材料；
- 只讲原因不回应观点；
- 强行添加对策；
- 使用模板但没有针对题干；
- 结论与分析不一致。

### AI 反馈示例

```text
你的答案完成了“解释是什么”，但没有说明该观点为什么成立。
建议补充材料中的两个现象，并说明它们如何共同证明题干观点。
```

---

## 9.3 提出对策题

### 评分维度

- 问题识别；
- 问题与对策对应；
- 执行主体；
- 具体措施；
- 执行方式；
- 资源与机制；
- 预期效果；
- 可操作性；
- 字数控制。

### 对策结构检测

```text
责任主体 + 目标对象 + 具体动作 + 执行方式 + 保障机制
```

系统不要求每条对策都具备全部字段，但应根据题目和字数判断完整程度。

### 对策评分示例

原文：

> 加强宣传，提高群众认识。

系统反馈：

```text
命中方向：宣传教育
问题等级：橙色
缺失信息：
- 宣传对象
- 责任主体
- 宣传方式
- 需要解决的具体问题

建议修改：
由基层政府联合社区，针对重点人群开展分众宣传和案例教育，提高群众参与治理的主动性。
```

## 9.4 应用文

### 评分维度

- 文种；
- 格式；
- 身份；
- 对象；
- 语气；
- 写作目的；
- 内容完整；
- 表达规范；
- 结尾；
- 字数。

### 格式检查

根据不同文种动态判断：

- 标题；
- 称谓；
- 正文；
- 结束语；
- 落款；
- 日期；

## 9.5 大作文

### 评分维度

| 维度 | 说明 |
|---|---|
| 立意 | 是否扣题、准确、稳健 |
| 中心论点 | 是否明确、集中 |
| 分论点 | 是否有层次、非重复 |
| 结构 | 是否完整、递进合理 |
| 材料结合 | 是否有效使用材料 |
| 论证 | 是否有因果、对比、举例等 |
| 语言 | 是否规范、准确、简洁 |
| 规范 | 是否符合字数、格式、卷面要求 |

### 重点分析

- 是否偏题；
- 是否中心论点过大；
- 是否分论点同义重复；
- 是否段落只有观点没有论证；
- 是否案例与论点不匹配；
- 是否套话比例过高；
- 是否结尾只喊口号；
- 是否材料使用停留在复述层面。

### 大作文输出

- 评分区间；
- 立意判断；
- 文章骨架；
- 分论点关系图；
- 论据有效性；
- 最薄弱段落；
- 最小修改方案；
- 可选重写路径。

# 11. 评分账本设计

## 11.1 单题评分输出

```text
预计得分：10.5 / 15
合理区间：9.5—11.5
置信度：82%
```

【修订】原文未定义置信度的计算方法。定义为「题目匹配系数 × 识别质量系数 × 证据通过率 × 复核一致系数」，分数区间半宽为「满分 × (1 − 置信度) × 0.3」，详见 [需求修订说明.md](需求修订说明.md) 第二节。置信度是系统对本次评分稳定性的自评，不是统计概率。

【修订】大作文、应用文格式与语言这类维度不是离散得分点，不套用得分点矩阵，改为按档次打分并写明理由（等级型维度）。得分点矩阵只用于要点型维度。

## 11.2 得分点矩阵

| 状态 | 含义 |
|---|---|
| 完整命中 | 基本完整覆盖 |
| 部分命中 | 方向正确但表达不完整 |
| 表达争议 | 可能属于合理同义表达 |
| 未命中 | 未体现核心内容 |
| 材料外推 | 超出材料或题目边界 |
| 重复 | 与其他得分点重复 |

## 11.3 评分冲突处理

当不同模型意见不一致时：

1. 重新检索材料；
2. 检查同义表达；
3. 使用第二评分模型；
4. 计算置信度；
5. 必要时提交人工复核。

# 13. 反事实增分系统

## 13.1 增分建议格式

```text
当前预计得分：63 分

优先修改项：
1. 补充大作文第二分论点的材料证据
   预计耗时：4 分钟
   预计提升：1—2 分
   优先级：高

2. 将“加强管理”改为具体责任主体和行动措施
   预计耗时：1 分钟
   预计提升：0.5—1 分
   优先级：高

3. 删除第 4 段重复论述
   预计耗时：2 分钟
   预计提升：0.5 分
   优先级：中
```

## 13.2 修改收益计算

系统只输出估计，不输出绝对承诺。

```text
缺口分   = 评分点分值 − 当前得分
预计增分 ∈ [缺口分 × 0.5, 缺口分]
排序依据 = 预计增分上限 ÷ 预计耗时
```

【修订】原公式中的「题型影响系数」未定义，且评分点分值本身已按题型设定，再乘系数属于重复计算，已删除。

需要向用户说明：

> 增分预测用于确定修改优先级，不等同于正式考试实际得分变化。

# 24. 主要风险与应对

## 24.1 AI 评分不稳定

应对：

- 【修订】默认单模型评分 + 规则校验证据；只对证据校验失败或低置信度的评分点送第二模型复核。每题都跑多模型会让成本翻倍，也达不到单题 30 秒的目标；
- 评分账本；
- 置信度；
- 人工复核；
- 争议样本训练。

## 24.2 参考答案误导

应对：

- 保存多个合理表达；
- 展示评分点而非只展示答案；
- 明确参考答案不是唯一答案；
- 支持答案申诉。

## 24.3 OCR 错误导致误判

应对：

- 必须提供识别确认；
- 低置信度内容不直接用于关键评分；
- 原图与文本并排；
- 支持一键回看。

## 24.4 用户过度依赖 AI

应对：

- 分层提示；
- 延迟展示参考答案；
- 强制二次修改；
- 迁移测试；
- 限制一键完整重写。

## 24.5 用户认为批改报告太复杂

应对：

- 首屏只展示三个最关键问题；
- 分层报告；
- 支持严格模式和快速模式；
- 支持语音讲解；
- 允许用户选择反馈深度。

# 25. 最终产品战略

本产品不应与市场竞争“谁的题库更多、谁的报告更长”，而应建立如下定位：

> 浙江省考申论的证据化评分与能力增分系统。

最核心的产品闭环是：

```text
看见问题
  ↓
确认问题
  ↓
理解原因
  ↓
完成最小修改
  ↓
获得增分反馈
  ↓
完成陌生题迁移
  ↓
确认能力掌握
```

真正的核心创新包括：

1. 评分账本：解释每个得分点和扣分点。
2. 错误因果诊断：解释用户为什么反复犯错。
3. 反事实增分：告诉用户改哪里最划算。
4. 答案版本系统：记录能力变化，而不是只保存报告。
5. 争议复核机制：允许用户反驳并改进评分。
6. 训练处方：生成有目标、有步骤、有通过标准的训练。
7. 迁移测试：验证用户是真的学会，而不是只改好原题。
8. 浙江省考评分配置：适配考试类别、年份和评分标准。
9. 教师校准体系：将人工经验转化为评分数据资产。
10. 考场能力模型：分析时间、书写和高压场景下的真实表现。

产品最终应从：

> AI 给申论答案打分

升级为：

> AI 解释分数、定位失分机制、指导最小修改，并验证用户能否真正提升。

这才是相比市场现有产品更有机会建立长期竞争力的方向。
